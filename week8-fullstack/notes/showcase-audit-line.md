## 1. 这条线是什么，不是什么

**是什么**：一条**按块推进、可随时暂停**的核查队列。每次消化一块板，做完记一行，下次从下一块继续。
它的节奏由**余量**决定，不由学习日程决定——这正是「单开一条线」的意思。

**不是什么**（三条，缺一条这条线就会开始和学习抢时间）：

1. **不是新增的并行线。** 2026-08-17 已拍板：W10 的并行线只有**英语 + 项目叙述**（`week10-plan.md` §5）。
   本线不进这个名单，也不占每日主线的时间盒。
2. **不是每日必做项。** 按 `LEARNING-PROTOCOL.md` §7 的固定优先级，它属「上周遗留实验与优化」那一档——
   **只有当天主线达到止步条件后才允许进入**。当天主线没收口，这条线就该是零进展，且零进展不算欠账。
3. **不是收口日的活。** 收口日（每周 D5）本来就满，把八块板的判定塞进去，
   结果只会是「凭印象铺开改」——那恰好和这条线要修的失效同型。

**一句话**：**它排队，不排期。**

## 3. 两个维度，两种触发方式（不要混用）

| 维度 | 问什么 | 判据 | 触发方式 |
|---|---|---|---|
| **① 数据时效** | 这一格的结论和**最新一次实测**还对得上吗？ | 对不上就翻档；`yarn verify:board` 保持全过 | **事件驱动**：每次有新实测、新收口，就核**受影响的那几格**——不必等排到这条线 |
| **② 表达形态** | A. 遮住 `h3` 与结论段，还能答出验收句吗？B. 能答出以后，是否仍要读完多屏正文才知道重点？ | 加严后的验收判据（roadmap 第八轮）+ 四条肯定面 + 阅读负担三问 | **排队驱动**：按本文件 §4 一块一块消化 |

**四条肯定面**（roadmap「目标与约束」，此处只作复检提问用，不重新定义）：

1. 同类对象 ≥ 3 个要相互比较 → 有没有让读者在脑子里建表的地方？
2. 量可比且差距本身是结论 → 差距是结论的那几处，出图了吗？
3. 信息有序或分层 → 用的是位置编码，还是「第一 / 第二」这类序号词？
4. 一块板的正文超过一屏 → 有没有一个不读正文就能读到的锚（一眼读数 / 矩阵 / 尺）？

**阅读负担三问**（2026-08-21 补入；它和“有没有图”不是同一件事）：

1. **主路径**：一块只回答一个问题时，读者能否先看到“问题 → 判断 → 必要边界”，还是摘要、命令、原始证据、复盘过程同时争抢注意力？
2. **重复量**：结论已经由位置、长度或矩阵编码后，紧邻正文是否又把同一结论完整说一遍？保留限定语不等于重复讲图。
3. **文案可读性**：一句是否同时压入结论、原因、反例、限定和动作；各卡是否反复使用同一种高度压缩的判断句。这里把本人所说的“AI 感”落实为可观察的句法与信息层级问题，**不推断文字来源**。

> 第 4 条只有“长页必须有锚”，是必要条件，不是长页通过条件。锚存在后仍把全部细节默认摊开，
> 依然属于阅读负担欠项。专题高度、字数等代理指标只用于定位高密度区域，不能替代人工判断，
> 也不能靠压字数凑过验收。

> 维度 ① 是**跟着学习走的**（新数据一到就该修），维度 ② 才是这条线的主体。
> 把两者混成一件事，会让「今天有没有新实测」决定「今天要不要返工八块板」——那是没道理的耦合。

## 4. 工作单元与两个阶段

**一个工作单元 = 15–20 分钟 = 一块板**（`AGENTS.md` 的小单元口径）。

### 阶段一：只判定，不改（八块，八个单元）

对一块板：遮住 `h3` 与结论段 → 自问该块的验收句 → 答得出 / 答不出 → 四条肯定面各过一遍 →
再过阅读负担三问 →
在 §5 记一行：**欠什么、欠多少、值不值得改**。

**阶段一不许动代码。** 这是整条线最容易破的一条纪律：看到一处不顺眼就顺手改，
结果是判定没做完、改动铺开、规模再次估不出来。

### 阶段二：按判定结果决定改哪几块（规模到阶段一末尾才知道）

阶段一全部做完后，拿着八行判定一次性决定：**改哪几块、每块改到什么程度、要不要全改**（大概率不必全改）。
届时更新 `BACKLOG.md` P2-4 的档位与规模，再排具体执行。

### 5.1.9 视觉编码维第一轮：共性欠口②「量的差距只写成数字」（2026-08-21）

阶段二前五轮全是折叠，属阅读负担；**视觉编码那一维一个单元都没动过**。
这一轮是第一次**往版面上加承载力**，而不是把文字藏起来——那才是「图形负责结论本身」的本意。

选它做第一轮的理由：§5.3 的共性欠口②一次覆盖剩余六个单元里的**四个**
（`W3Board` 2 + `W6Day4Board` 2），因为这两处是**同型数据、同型缺陷**。

**改了什么**：`charts.tsx` 里加三个小构件，两块板共用——

- `parseQuantity`：只认「整条字符串就是一个量」的格子。
- `metricRowScale`：一行之内共用一把尺，且**单位必须一致**；拿不到就整行不画。
- `MetricBar`：行内对照条，数字照旧逐字显示在条的上方。

> **没有硬套 `HBarChart`。** 它是单序列、全局同轴的横条图，适合「十三个专题各出现几次」那种同单位排序；
> 这里要比的是**同一个指标的前后**，而一张表里既有「次数」又有「毫秒」——同轴就是错的。
> 所以用的是同一套长度编码语言，落成十来行的行内条，不是新造一个图表组件。

**两条自律，写进代码注释里**：

1. **只认整条即量的格子**。混了别的词（`3 suites / 9 tests 通过`）、带方括号（`["name_1"]`）、
   破折号占位（`—`）一律不画。
2. **一行共用一把尺，跨行不比**。单位不同不画。

**实测行为验证**（这几条比「画得好不好看」更要紧）：

| 组 | 行数 | 画出的条 | 说明 |
|---|---|---|---|
| `W6Day4` · W3 组 | 4 | **6** | `indexesUsed: [] → ["name_1"]` **不画**——类别型 |
| `W6Day4` · W5 组 | 3 | **8** | 三行都有基线列，`fib(40)` 的基线是 `—` 不画 |
| `W6Day4` · W6 组 | 4 | **0** | **整组一条不画**——数据库来源、隔离方式全是类别型对照 |

最后一行正是判据要的那句「没有比较价值的东西不能画成有刻度的量」。
它也和 8/21 那行判定对上了：「阶段二只改 `EvidenceLayers` 中 W3 / W5 的数值呈现，W6 类别型对照不动」。

**长度现在说出了原来要算才知道的话**：

- `collectionScans 3 → 0`、`totalDocsExamined 15 → 0`：满条 → 一个贴底的短记号。
  **零画成记号不画成空白**——「降到 0」是结论，空白会被读成「没有数据」。
- `executionTime 12ms → 3ms`：297px → 74px，四分之一一眼可见。
- `并发 /ping 峰值约 378ms → 约 2–3ms`：满条 → 一个小点，而**灰色的空闲基线条就在旁边**，
  于是「回到了基线」这句结论第一次由版面承担，而不是靠读者比对两个数字。
- `maxHeartbeatGap 1154ms → 102ms`：11 倍差直接是长度差。
- `fib(40) 1111ms → 1124ms`：两条几乎一样长——**这也是结论**（worker 卸载不让计算本身变快）。

> 区间值（`约 2–3 ms`）取上界画条，**原文逐字保留在条的上方**，「约」「峰值」一个字都没丢。
> 理由：这一行的结论是量级差（约 150 倍），区间内的精度对它没有影响。

### 5.1.10 视觉编码维第二轮：共性欠口①「互斥切换」（2026-08-21）

`AuthBoard` 的三条结果路径与 `W6Board` Day 3 的三条轨道是**同型缺陷**：
同类对象由 `tablist` / `group` 切开，**一次只看得见一条**，而三者停在第几层、彼此差几格
**差距本身就是结论**——读者被迫在脑子里建表。这正是第 1 条肯定面要防的事。

**做法：不重新设计那两块板，只补一条「把被切开的对象按位置摆在一处」的全览。**
`charts.tsx` 加一个 `StopMatrix`，两块板共用：一行一条路径，横轴是同一条链的各段，**段位就是停止点**。
逐段详情仍由下方原有的视图负责，切换器一个字没动。

**三种格子，各自表示不同的事**（这一点比配色重要）：

- **不适用**（斜纹）——这一段不属于本路径。`AuthBoard` 的「无效身份 · 401」从第 4 段才开始，
  前三段是登录链，它根本不经过；画成「没走到」就是错的。
- **走过**（实色）
- **停在这里**（描边 + 状态码）

**实测校验**（数值直接对着数据里的 `stopAt` 核）：

| 板 | 路径 | 停在第几段 | 数据里的 `stopAt` |
|---|---|---|---|
| `AuthBoard` | 无效身份 · 401 | 第 5 段「认证」 | 4 ✓（另有 3 格不适用） |
| | member · 403 | 第 6 段「授权」 | 5 ✓ |
| | admin · 200 | 第 7 段「资源」 | 6 ✓ |
| `W6Board` Day 3 | 无 Token · 401 | 第 3 段「validateToken」 | 2 ✓ |
| | member · 403 | 第 4 段「requireRole」 | 3 ✓ |
| | admin · 200 | 第 8 段「React render」 | 7 ✓ |

**「各差一格」这句话现在是看出来的，不是数出来的。** 两块板都能一眼读到「两道门紧挨着，
认证过了才轮到授权」——`AuthBoard` 是第 5、6 段，`W6Board` 是第 3、4 段。

**横轴的短名是压缩不是新写**：`AuthBoard` 原来没有短名，这次给 `AUTH_CHAIN` 每段补了一个 `short`
（登录 / 比对 hash / 签发 JWT / 带 token 请求 / 认证 / 授权 / 资源），**逐字压缩自各段既有的 `title`，
不引入任何新说法**。`W6Board` 的 `FULLSTACK_STAGES` 本来就有短 `label`，直接用。

**无障碍**：`role="table"` + 行列表头；`aria-label` 完整念出三条路径各停在第几段哪一段
（读屏拿到的是「member · 403 停在第 6 段「授权」」这样的整句，不是一堆色块）。

**验收**：`yarn typecheck` 过；`yarn verify:board` **421/421**；
1280px / 375px、深浅色各核一次，四种组合下全览均无横向溢出。**未部署。**
