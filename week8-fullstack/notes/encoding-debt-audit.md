## 采集方法

构建后的 `dist-showcase` 起本地静态服务，Chromium 1440×1000 复习态逐页采集。每页采集前：

1. 按行为识别专题按钮（点击后 URL 的 `topic` 参数发生变化的按钮），因此不依赖各板不统一的切换器标记；
2. **点开该页所有复习门**（多数专题默认只渲染门本身，不点开量到的是门不是内容）；
3. **展开该页所有折叠区**。

因此表中屏数是**阅读上限**，不是默认阅读量：渐进层级做得好的页面在本表里反而更高。
`release` 三页的默认收起态实测为 1.83–1.89 屏，本表记的是全展开后的 3.7–3.91 屏。

**列的含义**

| 列 | 度量 |
|---|---|
| 屏数 | `scrollHeight / 视口高`，全展开态 |
| 正文字数 | `p / li / dd` 内直接文本节点字数合计，不含标题、标签、代码块 |
| 编码组件 | `svg` 元素 + `charts.tsx` 的 `.chart-wrap` + 逐帧播放控件，三者之和 |
| 结论锚 | `data-anchor` 标注数 |
| 最大同类组 | 同一父节点下类名首段相同且 ≥3 的兄弟组中最大的一个（已排除专题条、图例、全站 tab 条） |
| 等距组 | ≥3 个同类对象且彼此宽度差 ≤10%、单列排列的组数。**这类组等于一个纯列表：同类对象没有用位置或长度编码任何东西** |
| 有几何编码组 | ≥3 个同类对象且宽度有差异或多列排布的组数 |

**一处已知噪声**：`deploy` 每一行的「最大同类组」都是 18，来自该板上一个常驻元素，不随专题变化，
读该列时应看「等距组 / 有几何编码组」两列。

## 读出来的四条

**1. 非文字编码组件在全站是稀缺的。** 61 个专题页里只有 **10 页**含 `svg`、`charts.tsx` 组件或逐帧播放控件，
分布为 `deploy` 4 页、`testing` 2 页、`auth` 1 页、`oauth2` 1 页、`runtime` 1 页、`release` 1 页。
**`observability` 12 页全部为 0**。这不等于那些页没有视觉编码——各板大量用 CSS 网格做矩阵与轨道，
它们计入「有几何编码组」而不计入「编码组件」，两列必须一起读。

**2. 结论锚目前只有 `release` 三页有**，其余 **58 页**为 0，即欠账清单。
按 roadmap 的规定，断言的生效范围随返工推进，不一次性铺开。

**3. 阅读上限最高的五页**（全展开态）：`deploy/evidence` 6.52 屏 3825 字、`testing/day4` 6.15 屏 1814 字、`observability/redproof` 5.81 屏 2464 字、`deploy/release` 5.13 屏 1904 字、`deploy/boundary` 4.77 屏 2194 字。
其中 `deploy/evidence` 与 `testing/day4` 已在核查线阶段二做过折叠处理，高的是上限而不是默认阅读量。

**4. 标杆板与其余板的正文量级差 5–15 倍。** `runtime` 的 8 个专题里有 7 个正文不足 200 字
（最小 101 字、屏数 1.5），只有 `lifecycle` 一页是 892 字。
也就是说标杆板的常态是**固定高度的可视化舞台加一百多字解说**，不是长文配插图。
其余板每页正文的中位数约 1198 字。这与开工判据「W5 四要素」第 3 条一致：文字降级为读数与解说。

## 下一步怎么用这张表

本文件只做判定。改动按 `BACKLOG.md` P2 与 roadmap 的排期推进，建议顺序：

1. **`W11` 剩余五块**按开工判据的编码表建（新板优先于存量返工，它是验证纪律是否生效的样本）；
2. **`observability`** 的 12 页在「编码组件 0 + 等距组存在」两列上同时命中，是存量里最集中的一块；
   其中 `redproof`（绿→红→绿的状态推进）与 `drill`（注入→症状→恢复）属**内容随时间变化**，
   是全站除 `runtime` 外仅有的两处适合逐帧播放的内容；
3. **`deploy` 十三块**继续按 `BACKLOG.md` 的理由延后，只挑等距组最多的两三页做局部补图；
4. `interview` 维持不纳入（材料索引，非关系图）。
