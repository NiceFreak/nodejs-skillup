## 5. 必须先修的事实与机制

### 5.1 服务端架构与认证

- W2 `middleware`：同步调用栈可以出现 A 进 → B 进 → C 进 → C 离 → B 离 → A 离；异步响应完成不能用
  “`next()` 阻塞到后续链条全部返回”解释，当前实测已经显示 async route 中 `next()` 可先返回，完成时点看 `finish/close`。
- W2 `request-shape`：必须分开写 Mongoose 方法调用、MongoDB 查询结果、Mongoose 返回给 repository 的 document/null，
  再由 repository 返回给 service；不能从 MongoDB 直接跳到 service。
- W2 `ownership`：当前 `updateUserService` 在过滤白名单前检查原 body 是否为空；只含 `role` 等非白名单字段时，
  展板所称“没有有效字段会被 service 拒绝”不成立。核心代码由本人处理，展板先如实标待修。
- Auth `register`：安全摘要由 Auth Service 构造，Controller 只包装 HTTP 响应信封。
- Auth `login`：相同 401 与文案只能证明不会通过直接响应枚举账号；已观察到时序差异，不能写成完全不泄露。

### 5.2 数据库与跨层链路

- W3 `match-index`：现有证据支持“扫描工作量 14 → 5、COLLSCAN → IXSCAN”，不支持“更快”的耗时结论。
- W3 `covered`：正反实验支持“本查询避免 FETCH”，不支持没有比较全集的“索引最高效形态”。
- W6 Day 4：请求下行与结果回程必须分轨；MongoDB 执行聚合、Mongoose/Repository 返回普通对象数组、
  Service 转换金额、Controller 表达 HTTP、前端补月份，不能画成单向十层交接。

### 5.3 W9 到 W11 的时间线

- W9 的 8080、公网面、四份站点配置与无 Token API 样例是 W9 D5 快照，不是 8/28 当前状态。
- 当前已实测：8080 无监听；80 新增 `/showcase/`；`users.http` 与 Postman collection 已串联 admin token。
- W10 假 active 必须保留“截至 8/21 的 W10 收口态”，并接上 8/27 W11 最小样本、修复验证与上线结果；
  不能把历史 pending 覆盖成“当时已经知道”，也不能继续把它写成当前 pending。
- W11 StagePlan 已 12/12 完成，“剩下两块等收口日”是失效的未来时态。
