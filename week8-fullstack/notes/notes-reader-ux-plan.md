# 学习笔记阅读模块体验改建设计

> 日期：2026-09-06  
> 范围：`week8-fullstack/src/frontend/` 的学习笔记阅读模块。只改展示资产，不修改学习代码或 Markdown 正文事实。  
> 基线：接入前复习状态共 51 份文档；现有样本中最长章节导航为 123 项。接入后为 53 份，数量继续由数据计算。

## 1. 设计契约

| 列 | 冻结结论 |
|---|---|
| ① 单一问题 | 阅读长篇 Markdown 时，怎样随时返回来源展板、切换笔记和章节，并保持当前阅读位置可见？ |
| ② 10 秒结论 | 返回目标、当前笔记和当前章节持续可见；桌面两侧目录各自滚动，手机从同一条阅读栏进入两种目录。 |
| ③ 对象与数据形状 | 三个导航对象：来源展板、文档列表、当前文档的 H2/H3 章节；正文继续使用页面主滚动。 |
| ④ 结论编码 | 三列位置编码职责；sticky 编码持续可达；独立滚动容器编码目录与正文互不带动；选中标记编码当前位置。 |
| ⑤ 视觉舞台 | 桌面为左侧笔记目录、中间正文、右侧章节导航；平板为左栏、正文和吸顶章节选择；手机为吸顶阅读栏加单列正文。 |
| ⑥ 文字层级 | 阅读栏常驻返回目标、当前笔记和当前章节；侧栏显示导航标签；Markdown 正文不复制到导航层。 |
| ⑦ 视觉记忆点 | 三条稳定纵向轨道：文档、正文、章节。两侧选中项随正文位置移动，但不改变正文滚动位置。 |
| ⑧ 图标策略 | 返回使用已有的方向箭头字符；仓库没有图标库，不为单个图标引入依赖。其它操作使用带标签的原生表单控件。 |
| ⑨ 动效策略 | 只有当前项进入侧栏可视区的方位调整；不使用平滑动画，不产生自动播放，reduced motion 下行为不变。 |
| ⑩ 验收证据 | 1440x1000、1280x844、390x844；返回深链、两侧独立滚动、当前项跟随、重名章节刷新、移动端两种选择器、键盘焦点、无横向溢出。 |

## 2. 响应式结构

| 视口 | 笔记目录 | 章节导航 | 阅读栏 |
|---|---|---|---|
| `>= 1400px` | 左侧独立滚动栏 | 右侧独立滚动栏 | 返回目标 + 当前笔记 + 当前章节 |
| `721-1399px` | 左侧独立滚动栏 | 阅读栏中的原生 `select` | 返回目标 + 当前笔记 + 章节选择 |
| `<= 720px` | 阅读栏中的原生 `select` | 阅读栏中的原生 `select` | 返回目标 + 两种选择器 |

侧栏外壳负责 sticky 和视口高度，标题与筛选控件不滚走；内部导航负责 `overflow-y: auto`。滚动到边界时不把滚轮继续传给正文。当前笔记或章节变化后，只调整对应侧栏的 `scrollTop`，不能调用会移动页面的滚动方法。

## 3. 路由与兼容边界

- `returnTab + returnTopic` 的成对白名单校验和 `noteReturnHref()` 保持不变。
- 数字章节和既有唯一标题继续使用原 `section` 值。
- 同一文档内的重名标题从第二项开始追加稳定序号；旧的无序号链接仍落到第一项。
- 手动滚动正文时用 `history.replaceState` 更新当前章节，不增加浏览器历史条目；显式点击章节仍沿用既有 hash 导航。
- 切换文档继续清除旧章节；跨笔记链接继续保留来源展板上下文。
