## 请分五项审查，逐项给结论

### 一、证据真实性（最高优先级）

逐条检查 `aiEngineerTopics.ts` 里 7 块的每个字段（`anchor` / `boundary` / `accept` / `memory`
以及各块的数组字段与 `sources[].ref`），判定为：

- **有据**：能在笔记或源码里找到对应（给出文件 + 行号）
- **过度推断**：有相关内容，但页面的表述更强、更具体，或加了来源里没有的细节
- **无据**：完全找不到

只报告后两类。对 P1 与 P3 的每个 `source` 字段，**逐个打开那个文件的那一行**确认代码片段真的在那里。

### 二、图形是否真的承担了结论

对 7 块每一块：遮住标题、10 秒结论和所有文字层，**只看 SVG 图本身**，回答该块的 `accept`（验收句）。

- 图讲不清、必须回去读文字才知道结论 → 记为不合格，说明缺什么
- 检查 `SHOWCASE-VISUAL-PROTOCOL.md` §3 那张「认知任务 → 首选形态 / 不合格替代」表：
  有没有哪块的实现实际上落在「不合格替代」那一栏（例如顺序类做成了「等宽卡片加序号」、
  分叉停止类没有真实拓扑、归属类只是一个列表）
- 检查图上是否有：线条压住文字、箭头指向不存在的对象、断头的边、标签与它说明的对象离得太远

### 三、断言质量（不要只看它是不是绿的）

`verify:board` 目前报告 1206 项全绿。**绿不等于对**。请抽查 §E 段（搜索 `E. AI 工程板`）：

- 有没有断言的选择器在页面上**选中 0 个元素**却仍然通过（空跑）
- 有没有断言量错了对象（例如量 SVG `<g>` 的包围盒——它会被组内文字标签撑大，量到的不是图形本身）
- 有没有断言只查「某段文字在不在」，而它声称守的是几何或拓扑
- 关键结论有没有对应断言：删掉数据层里某条关键内容，断言会不会红？
  （可以真的改一下再跑，跑完记得改回来）
