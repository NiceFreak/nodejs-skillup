## 0. 这份方案要解决的问题

方案初稿（8/18 上午）写的是「可视化 D1 的观测契约」。**D2 当天收口，方案的对象随之变了**：
现在有一份冻结的契约，和一次真正上线的实测——**两者之间的差，才是这周最值钱的东西**。

D1 单独看是一份纸面承诺，D2 单独看是一串验证记录；合起来才有下面三个缺口值得做图：

1. **契约与实测的对应关系散在两份文件里**。§5.1 的十个字段 ↔ D2 §11 那行真实 NDJSON；

   读者拿到的是两份各自完整的文档，拿不到**「说好的」和「真做出来的」并排**。

2. **D2 最值钱的一课藏在「执行期新增事实」的编号列表里**。
   `nginx -t` 全过、`redact` 配好了、`eslint` 也过了——**三个绿灯之下仍有真实缺陷穿过去**：
   `proxy_set_header` 的 location 级屏蔽、`log_format` 定义了但 `access_log` 没指定它、
   `err.message` 里的查询串凭据（redact 只认对象路径，不碰字符串）。
   这四条是同一族的，现在它们分散在 §2.3、§11 与 `nginx.conf-http-logging.md` 三处。

3. **盲区已经被消灭了一半，但「哪一半没消灭、为什么不该消灭」没有形态**。
   `close` 兜底上线后，四个请求终局里 Node 侧仍有一格是空的（请求没进 Node）——
   那一格**本来就该由 Nginx 那条流回答**。这是分工，不是漏洞；写成文字读者分不出来。

本方案仍不发明新语法，只做一处扩展（§2.2 的 `contract` 档位），
并把整块板的骨架定为**契约 → 实测 → 差在哪**。

## 4. 板块设计（六块）

> 每块只回答一个问题。第 ⑥ 块是 D2 之后新增的，也是**建议先做的代表页**。

### ① 盲区：改造前后，一次请求留下什么（`topic=blindspot`）

**空间编码**：一条请求生命线上的四个终局（正常 `finish` / 客户端断连 `close` / 没进 Node / 进程级错误），
每个终局下面**两条**证据轨道：上排 = 8/17 之前，下排 = 8/18 之后。

**一眼结论**：上排四格里只有两格留下过日志，而其中一格（进程内出错）留的是
**与请求行对不上的 `console.error`**——并发时根本不知道哪条错误属于哪次请求，等于半条证据。
下排**三格有了**，剩下的那一格（没进 Node）**永远不会有**——因为它该由 Nginx 那条流回答。
**盲区不是被填满的，是被分清了归属。**

> **落地时的一处自我修正（8/18）**：本方案初稿写的是「上排只有一格有日志」。
> 按 `app.js` 的实际代码，改造前 `console.error` 一直存在，只是**没有关联 id**——
> 是两格，不是一格。展板按代码事实渲染，此处按展板改回来。
> 这正是「先核有没有说谎，再谈补内容」那条纪律的一次自用。

**档位不是四格都一样**：`finish` 与 `close` 是 **已实测**（验证①③）；
「没进 Node」是 **已拍板**（D4 演练才注入验证）；「进程内出错」也是 **已拍板**——
形态来自已上线代码，但 D2 的七项验证没有单独抓一条错误日志原文。
未到实测的两格必须把**证据差在哪**写在格子里，不能靠档位标签一个词带过。

**证据**：`close` 那格挂 D2 验证③ 的实测（100 KB body 限速 → `requestStatus:"close"` 恰 1 条，`uniq -d` 无重复）；
并写清首次尝试 `--max-time 0.05` 打 login 没造出断连（bcrypt 快路径 4 ms 全走 finish）——
**那是测试方式问题，不是实现缺陷**。这条「验证方法本身可能失效」值得留在板上。

**复习门**：先只给「用户说超时了」，问「你现在能查到什么」，再揭示两排轨道。

### ② 字段契约的销账（`topic=fields`）

**空间编码**：左列 D1 契约的十个字段，右列 D2 实测那一行 NDJSON 的实际键，中间连线。

**一眼结论**：**十个字段一次上线全部到位**（`method` / `path` / `statusCode` / `requestId` /
`duration` / `ip` / `ua` / `errorType` / `requestStatus` + time），
契约里的「可选字段」也按原样留在核心之外（`requestIdSource`、入口端口）——
**契约没有在实现时被偷偷缩水**，这是销账的意义。

**必须紧邻的一条**：`requestId` 有两种形态——Nginx 传来的 32 位 hex，和本地兜底的 `local-<uuid>`。
后者不是降级失败，是**自解释的分支**：拿 `local-` 开头的 id 去 Nginx access.log 里 grep 不到，
第一反应应该是「这个请求没走反代」，而不是「日志丢了」。

**脱敏单独一段**，接 ⑥：四道闸按强制力排序——
不记 body（设计）→ `redact` 对象路径（配置）→ `eslint no-console`（机器强制）→ review（人）。
D2 验证② 证明真正挡住密码的是**第一道**；而唯一漏出去的那条是 review 抓的——细节进 ⑥。

### ③ 日志旅程：一根 id 挂在九个地方（`topic=journey`）

**空间编码**：两条并排泳道（Nginx access.log / Node journald），横轴时间，
一根横跨两泳道的线 = `request_id`；**线在 Nginx 侧分叉成 9 个挂点**（按 site 分组：80 三个、443 三个、8080 两个、8081 一个）。

**一眼结论**：D1 写的是「四份 server 块」，真正要动的是 **9 个反代 location**；
**少挂一处，那个面的请求就变成 `local-` 开头**——不会报错，不会有人告诉你，
只有拿着 id 去两条流里各查一次才发现。

**第二条结论（时间口径）**：Nginx 记 `+08:00`，Node 记 `Z`。
**目标不是让两个数字长得一样，是让差异显式且有据可查**（P2 的原话）——
所以偏移量写在每一行里，runbook 写死「减 8 小时」，而不是去动 systemd 单元把不一致转移到别处。

**第三条（口径）**：`rt=$request_time`（Nginx）与 `duration`（Node）是两个数，前缀写死是为了排障时不看串。

**证据**：D2 验证④⑤ 实测（响应头 `X-Request-Id: 63245c0a…`；Nginx access.log 1 条 + journald 1 条）。

### ④ 阈值从哪来（`topic=thresholds`）

**空间编码**：四条**距离尺**，每条尺三个点——今天的实测值 → 红线 → 出事点。尺长 = 从报警到出事的动作时间。

```text
内存   available 1304 MB ──────────────┤ 200 MB ├─ OOM（swap=0，无征兆直接被杀）
磁盘   可用 31 G ─────────────┤ 4 G ├── 写不进去（演练水位已占 26.5 G）
证书   剩 86 天 ──────────────┤ 15 天 ├─ 过期（续期失败手修 5–7 天 × 2 缓冲）
日志   已生效 500 M（占用 272 M）───────┤ 500 M ├─ 吃掉磁盘（与磁盘红线同一条链）
```

**一眼结论**：**没有一条红线定在故障点上**，全部定在「还来得及做点什么」的位置。
第二条：内存留得最紧（1304 的 15%），因为 **swap = 0 把「变慢」换成了「直接被杀」**。

**档位对比是本块的第二层信息**：四条里只有 journald 那条是 `measured`（D2 已生效，占用 272 M），
其余三条仍是 `contract`——**检查脚本 D3 才写，今天没有任何东西会真的报警**。
右侧强制挂「报出来我该做什么」，凑不出动作的阈值不算判据。

### ⑤ 演练分档与三信号定位（`topic=drill`）

**空间编码（上半）**：四类故障 × 三档注入距离（A 同机可逆 / B 受控目录 / C 必须隔离）。

**一眼结论**：四类全部落在 A、B，**C 档整列是空的**——空列不是没画完，是本周主动收窄
（OOM 属 C，唯一生产机同时扛五个公网面）。规则钉在旁边：**写不出回滚命令的那一类，本周不做。**

**空间编码（下半）**：三信号定位表——五面 curl / `/health` 直连 / `systemctl is-active`。

**一眼结论**：**五面 curl 单独不足以分层**（全 502 时 Nginx 挂和 Node 挂长得一样），
`/health` 是砍掉最后这一半的刀——**而这把刀 8/18 已经磨好了**（D2 上线，验证⑥ 实测 200）。

**必须紧邻的一条**：`/health` 有意不读 `mongoose.readyState`——
不是遗漏，是「Mongo 挂了我也没有可执行的动作」这条可操作性判据的结果；Mongo 故障走业务 500 + `errorType` 暴露。
同理它有意不暴露公网（`location / { return 404; }` 天然挡住），少一个攻击面。

### ⑥ 三个绿灯各自漏掉什么（`topic=falsegreen`）—— 代表页，建议先做

D2 换来的最可迁移的一块，**换任何技术栈都成立**：自动检查全绿 ≠ 语义生效。

**空间编码**：三列绿灯（`nginx -t` / `pino redact` / `eslint no-console`）× 每列下面挂它**放过去的实例** ×
最右列「最终是谁抓到的」。

| 绿灯 | 它检查的是 | 放过去的实例 | 谁抓到的 |
|---|---|---|---|
| `nginx -t` | 语法 | `proxy_set_header` 写在 server 级会被 location 级整族屏蔽 | 事前推理（P1）+ 验证⑤ 可证伪 |
| `nginx -t` | 语法 | `log_format obs` 定义了，`access_log` 没指定它 → 仍是默认 combined | 本地副本阶段自查 |
| `pino redact` | **对象路径** | `err.message` 里拼了 `req.url`（含查询串凭据）→ 以**字符串**形式落盘 | **review** |
| `eslint no-console` | 裸 `console.*` | 拦不住 `logger.error(obj, msg)` 的 msg 参数 | 同上（同一条缺陷的另一半） |

**一眼结论**：**四条实例里，只有一条是被自动手段挡下的**；一条靠事前推理，两条靠人眼。
第二条结论：`redact` 那条的修法是**断开两个通道**——源头改 `req.path`（不含查询串）+ 出口把 msg 改成纯描述。
只堵一头都不够，这是「凭据泄漏要断源也要断口」的具体形态。

**用纠错三段式渲染**（❌ 原以为 → ⚡ 实际机制 → ✅ 修正），复用 `W6Day4Board.tsx` 的 `Corrections`。

**与 ③ 的边界**：③ 讲这根 id 该挂在哪里，这块讲**为什么挂错了还看起来是对的**。

### 明确不单独成块

- **冲突自查七对**：挂到对应格子上（例如「path 用 `req.path` 不含查询串」同时出现在 ② 与 ⑥），
  板头只留一行「七对全过」状态。单独成块会变成一页文字。
- **runbook 五段式**：D5 才有内容。
- **D2 §3 的 P1–P5 完整答案**：结论进格子，推理进 notes tab。

## 12.6 阶段 2 执行记录（2026-08-18 同日）

### 落地内容

**③ 日志旅程**（`topic=journey`）

- **一眼结论用三个数并排**：`4 份 site → 9 个反代 location → 1 份 access.log`。
  中间那个数标红，因为它是**契约与配置的精度差**：D1 写的计数单位是 server 块，
  真正要挂 header 的单位是反代 location。
- 紧跟一句代价：**改漏一处不会报错，也不会有人告诉你**——那个面照常 200，
  只是 requestId 变成 `local-` 开头，只有拿着 id 去两条流各查一次才发现。
- 四步旅程做成两条泳道（Nginx / Node 各自的色带），每步挂档位。
- 九个挂点按 site 分四张卡，各自带**静态 location 为什么不挂**的一行——
  不挂不是遗漏，是它根本不反代，挂了也没有下游读这个头。
- **三个「两套」表**（落点 / 轮转 / 时间戳）：三行里没有一行共用。
  这张表是「为什么必须有一根 id」的完整答案——它不是为了好看，是两条流之间唯一的连接件。
- **时间戳不统一单独成段，并且写清它是拍板不是待修**：给出选了什么（接受 `+08:00`，
  偏移显式 + runbook 换算）与没选什么（`TZ=UTC` 只是把不一致从「Node vs Nginx」
  转移成「Nginx vs 系统其余部分」）。同段挂上 `rt=$request_time` 与 `duration` 两个口径。

**② 字段契约销账**（`topic=fields`）

- **销账要同时看两个方向**：`9/9` 必有字段全部到位（没缩水），`0/2` 可选字段未实现
  ——而契约写的就是「不进核心契约」，所以这是**照做，不是欠账**（没加码）。
- 十一行对照表（十行契约 + 实测多出的一个键）：契约措辞 → 实测键 → 没有它答不出什么 → 档位。
  两个可选行用灰底 + `已拍板` 标出来，不混进已兑现的行里。
- 实测比契约多一个 `level`（pino 自带）。记下来是因为**销账的「多」也要有交代**：
  它属库的形态，不是实现加码。
- **脱敏四道闸按强制力排**（设计 → 配置 → 机器强制 → 人），每道挂「今天实际起了什么作用」。

### 这一块真正的收获：第二道闸今天没起过作用

四道闸排完之后暴露出一条我在 D1 D2 都没意识到的事实：

> **今天真正挡住密码的那道闸，和配了一整页的那道闸，不是同一道。**

验证② 的 `PASSWORD_NOT_FOUND` 是**第一道闸**（中间件根本不把 `req` 记进日志对象）的功劳；
`pino redact` 的五条路径**今天一条都没有被触发过**——因为日志里压根没有 `req.*` 这样的路径可供它匹配。
它不是当前的主防线，是「万一将来有人把 req 记进去了」的保险。

这条与 ⑥ 那块的第三条实例（`err.message` 里的查询串凭据）咬合得很紧：
**当时以为 redact 会兜住，实际它既没兜住那条，也没在别处生效过。**
把四道闸按强制力排出来，才让「以为在起作用」和「实际在起作用」分开。

### 执行期修的两处（都是截图才看得见的）

1. **`.zero` 这个类名对「9」是语义错**。一眼结论里标红的那个数不总是 0——

## 12.7 按新验收判据返工四块（2026-08-18，本人反馈「每块板都充斥巨量文字」）

### 起因与结论

本人提出：这两周的板全是密集文字、没有配套视觉辅助，「不引图表框架 / 不把颜色当成果」这类标准可以适当调整。

核对原文之后的结论是**标准不该放宽**——那四条写的都是**成果判据**
（防「加个图标就宣布做完了」），从来没禁止视觉编码。丢掉的是限定词「当作可视化成果」，
再加上 roadmap 那条「图形只负责关系，结论保留文字」，十七块累积下来就成了现在这样：
**每块板都能通过旧验收（不读完整段也能判断），因为结论被写成了一句大标题**，版面本身不承担它。

改法写在 [`visualization-optimization-roadmap.md`](../../week8-fullstack/notes/visualization-optimization-roadmap.md)
第八轮：补肯定面四条、把「图形只负责关系」改成「图形负责结论本身」，
并把验收判据加严为——**遮住这块板的标题与结论段，仍能答出它的验收句**。

| ⑥ 假生效 | 表格，「四条全穿过去」要逐格读文字 | **三道闸横在通道上 + 四条从左穿到右的轨迹**。闸画成上下两截、中间留口；轨迹在某格断掉才表示被拦住——四条一次都没断，零命中成了图形事实 |
| ① 盲区 | 四张卡片，各自两条轨道 | **4 终局 × 2 时点的真矩阵，行首带合计**；格子用 ● / ○，「上排 2/4、下排 3/4」可数，那个唯一的 ○ 一眼就看得见 |
| ③ 日志旅程 | 纵向列表 + 左侧色带 | **两条真泳道 + 一根从上贯到下的 id 竖线**，卡片各伸一小节接到线上，交叉点（X-Request-Id 请求头）单独占一行——「串起两条流的只有这一根 id」从此是画出来的 |
| ② 字段销账 | 11 行表格 | 表中加一列**连线**：接上的实线加圆点，断开的虚线断在 ✕ 上。「9 条对上、2 条断开」可数，不必逐行读实测键 |

③ 是四块里最刺眼的一处：那块板的一眼结论就是「串起它们的只有这一根 id」，而返工前画的是一个列表。

### 断言也跟着换了形态

这次新增的四条断言**不再查页面上有没有某句话，而是量图形事实**：

| 断言 | 量的是什么 |
|---|---|
| 四条轨迹都完整贯穿 | 每行 `.w10-corridor-line` 的宽度 / 轨道宽度 > 0.98 |
| 行首合计与实心格数一致 | `.w10-grid-rowhead b` 的文本 == 实际 `.has` 格子数 |
| 两条泳道 + 一根贯穿的 id 线 | `::before` 存在、四步、两个 lane 类 |
| 连线 9 接上 / 2 断开 | `.w10-link.linked` / `.broken` 计数 |

**这是本轮方法上的实质变化**：以前断言只能拦「写错了」，现在能拦「图和数字各说各话」——
比如把行首合计改成 3/4 却没改格子，断言会响。

### 复核仪式（人工，有意不做机器断言）

每块板落地后，截图核对那一步加一道：**遮住 `h3` 与结论段，自问一次该块的验收句**。

不写成脚本是有意的——「结论有没有被版面承载」是判断题，硬做成代理指标
（例如「非文字编码元素数 / 正文字数」比值）只会被凑数满足，
那正好是本板 ⑥ 讲的同一种失效。**这道闸的强制力等级是「人」**，
写下来是为了让它至少存在，不是为了让它自动化——与 ② 那四道闸的排法同一套逻辑。
