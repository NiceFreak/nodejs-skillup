## 0. 这份方案要解决的问题

D1 的产出是一份**已冻结的契约**（Q1–Q15 全部作答、冲突自查七对全过、§5 四张表填满）。
它作为文档已经完整，但作为「学习成果」有三个可理解性缺口——**与 W9 的三个缺口不是同一组**：

1. **因果链被表格切断了**。四张表各自完整，但一条因果要跨表才拼得全：
   「requestId 从哪来」= §5.1 一行 + §5.2 旅程图 + Q4 三处；
   「磁盘红线为什么是 4 GB」= §5.3 取值 + §5.5 的 31G 基线 + Q13 的 26.5G 演练水位。
   读者拿到的是四张结论表，拿不到**结论是怎么被逼出来的**。

2. **现状与承诺混排，且这一版比 W9 更极端**。§5.1 的十个字段里，`app.js` 今天真正打出来的只有四个；
   §5.2 那张旅程图**整张都是明天的形态**。W9 板至少有一半是实测，
   **W10 D1 实测的只有 §5.5 那七个数字**。做成图之后极易被读成「已经这样了」——
   这正是 8/14 那次「展板说谎六处」的同一个机制。

3. **两个盲区是本周所有改造的「因」，却排在 §2.2 正文里**。
   「只监听 `finish` → 客户端断连一条日志都不留」和「脱敏是巧合不是设计」，
   排版权重跟旁边三条普通事实一样。它们不是背景，是起点。

本方案的工作仍然不是发明新语法，是把 D1 的内容接到已验证的语法上；
只在一处做最小扩展（§2.2 的 `contract` 档位）。

## 4. 板块设计（五块）

### ① 盲区：现在一条请求留下什么（`topic=blindspot`）

**空间编码**：一条请求生命线上的四个终局并排——正常走完（`finish`）、客户端断连（`close`）、
没进 Node（反代层挂）、进程级错误。每个终局下面挂一条「日志证据」轨道。

**一眼结论**：**四个终局里只有一个留下了日志**，另外三条轨道是空的（unknown 虚线）。

**与 W9 ② 故障分叉的边界**：那块问「两个 502 靠什么分叉」，这块问「分叉之前，你手上有没有可看的东西」。
一个是判断力，一个是判断力的前提。

**复习门**：先只给「用户说超时了」这一句，问「你现在能查到什么」，再揭示。

**必须紧邻的一句**：这不是 bug，是 `app.js` 只监听 `res.on('finish')` 的**必然结果**——
所以 D2 的 `close` 兜底不是补丁，是补上一个从来没有过的分支。

### ② 字段契约与三道防线（`topic=fields`）

**空间编码（上半）**：三列——字段 / 今天有没有（`app.js` 现状）/ 没有它答不出的那个问题。
不照抄 §5.1 的五列表，把「取值来源」降为悬浮细节。

**一眼结论**：**十个必有字段里，今天只有四个存在**；缺的六个恰好覆盖排障最先问的四件事——
哪一次请求（requestId）、走完了没有（请求状态）、什么类型的错（错误类型）、谁发的（来源 IP/UA）。

**空间编码（下半）**：脱敏的三道防线按**强制力深度**排列——
`pino redact`（配置层，机器强制）→ 全走 pino / 禁裸 `console.log`（纪律层，人强制）→ review（人工层）。
**一眼结论**：只有第一道是机器强制的，另外两道靠人；所以「永不入日志」四条必须写死在配置里，
而不是写在心里。

### ③ 日志旅程与两个断点（`topic=journey`）

**空间编码**：**两条并排泳道**（Nginx access.log / Node journald），横轴时间，
一根横跨两条泳道的线 = `request_id`。四步落点：Nginx 生成 → `proxy_set_header` 传头（四份 server 块全部）
→ Node 中间件直读 + pino 记 → 响应头回写。

**一眼结论**：两套落点、两套轮转、两套时间口径，**串起它们的只有这一根 id**；
四份 server 块缺一份，那个面的请求就是一条没有 id 的孤儿日志。

**两个断点做成判定，不是做成叙述**：

- Nginx 有 / Node 无 → 请求**没进 Node**，锁 Nginx 层
- Node 有且状态 = `close` → **客户端断开**，不是服务端 5xx

**必须紧邻的口径**（否则明天排障必踩）：Node 的 `duration` 与 Nginx 的 `$request_time`
**本来就不是同一个数**——前者从中间件入口起算，TLS 握手、排队、body 未读完都不在里面。
两者的差不是 bug。

### ④ 阈值从哪来（`topic=thresholds`）—— 建议作为代表页先做

W9 板没有这个语法，而它是 D1 最值钱的一块：**四条红线没有一条是拍脑袋定的**。

**空间编码**：四条**距离尺**，每条尺上三个点——
今天的实测值 → 红线 → 出事点。尺的长度就是「从报警到出事我有多久」。

```text
内存   available 1304 MB ──────────────┤ 200 MB ├─ OOM（swap=0，无征兆直接被杀）
磁盘   可用 31 G ─────────────┤ 4 G ├── 写不进去（演练水位已占 26.5 G）
证书   剩 86 天 ──────────────┤ 15 天 ├─ 过期（续期失败手修 5–7 天 × 2 缓冲）
日志   journald 248 M / 无上限 ─┤ 500 M ├─ 吃掉磁盘（与磁盘红线同一条链）
```

**一眼结论**：**没有一条红线定在故障点上，全部定在「还来得及做点什么」的位置**。
第二条结论：内存那条留得最紧（1304 的 15%），因为 **swap = 0 把「变慢」变成了「直接被杀」**——
有 swap 时你有时间反应，没有时你没有。

**右侧强制挂「报出来我该做什么」**：凑不出动作的阈值不算判据（§2.4.6）。这一列空着的格子就是坏阈值。

**必须紧邻的一句**：这四条红线**今天全部是 contract 档**——检查脚本还不存在，
证书今天剩 86 天，别把这张图读成「正在告警」。

### ⑤ 演练分档与三信号定位（`topic=drill`）

**空间编码（上半）**：二维矩阵——纵轴四类故障，横轴「注入点离生产有多远」（A 同机可逆 / B 受控目录 / C 必须隔离）。

**一眼结论**：四类全部落在 A、B 两档，**C 档整列是空的**——空列不是没画完，是本周主动收窄
（OOM 属 C，唯一生产机同时扛五个公网面，不做）。这个空格子必须画出来。

每格挂三件套（注入 / 止步 / 回滚），并把这条规则钉在矩阵旁边：
**写不出回滚命令的那一类，本周不做。**

**空间编码（下半）**：三信号定位表——五面 curl、`/health` 直连、`systemctl is-active`
三个信号的组合，落到四类真实故障上。

**一眼结论**：**五面 curl 单独一条不足以分层**（全 502 时 Nginx 挂和 Node 挂长得一模一样），
`/health` 是砍掉最后这一半的那把刀——而它今天还不存在（D2 新增）。

**复习门**：先给「五面全 502」，问「现在能确定是哪一层吗」，再揭示。

### 明确不单独成块

- **冲突自查七对**：抽象度高、缺空间结构，单独成块会变成一页文字。
  做法是把真正改变了结论的那几对**挂到对应格子上**（例如「path 用 `req.path` 不含查询串」
  = 脱敏清单与字段契约打架后的产物），板头只留一行「七对全过」的状态。见 §11 决策 2。
- **runbook 五段式**：D5 才有内容，现在做是画空表。
- **§2.4 七则概念**：notes tab 读原文。

## 7. 口径边界总表（本次最容易做错的六处）

| # | 边界 | 做错会变成什么 |
|---|---|---|
| 1 | Node `duration` ≠ Nginx `$request_time` | 明天把两者的差当成新 bug 查半天 |
| 2 | 「留下日志」≠「查得到」 | 两侧都没有记录时，读者以为是日志丢了，实际是请求根本没到 Nginx |
| 3 | 四条阈值是 contract，检查脚本尚不存在 | 图看起来像一套正在运行的监控 |
| 4 | §5.5 的 available 1304 MB 与 W9 的 1388 MB 是同一台机不同时刻 | 被读成两处事实矛盾 |
| 5 | 演练的「首个症状」是**预测**，D4 会对照修正 | 画得像实测，D4 的偏差就没有对照价值了 |
| 6 | 证书今天剩 86 天，红线 15 天 | 红线画得醒目会被读成「正在告警」 |

第 3 条与第 5 条是本板的主要说谎风险来源，`verify:board` 应对它们各加一条断言（档位标签存在且非空）。
