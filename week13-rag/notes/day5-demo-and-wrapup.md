## 5. 失败时怎样继续

| 现场状况 | 动作与讲解 | 仍能交付的内容 |
|---|---|---|
| 页面未启动或无法登录 | 使用已验证的本地预览；若仍不可用，直接切终端脚本与讲稿，不现场修改认证逻辑 | 相同 dev 记录、来源和对照数字 |
| Python 依赖不齐，`verify` 失败 | 停止本次重算，使用仅需 Python 标准库的 `summary`/`case`；说明“这里回放 D4 证据” | 已记录生成与原文；不声称现场重算成功 |
| 检索或 context 与记录不一致 | 保留错误提示，使用静态证据，登记待查的输入/配置/版本 | 展示历史结果及可重复性检查用途，不覆盖冻结文件 |
| 被要求现场调用新问题 | 说明当前主线使用固定已验证 dev 示例；新问题单列开放实验，先明确输入和调用范围 | 主讲按预算完成，探索性调用不混入本轮结果 |
| 遇到无法确定的技术问题 | 回答“当前证据能确认的是……；……还未验证，我会用……区分” | 留下可执行验证方法，不虚构结论 |
