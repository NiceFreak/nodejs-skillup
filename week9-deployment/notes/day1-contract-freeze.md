## 2. 从代码读到的事实（D1 的决策输入）

以下是今天读代码得到的**事实**，不是建议。它们直接约束第 4 节的答案。

### 2.1 可部署的 Node 应用只有一个

全仓库唯一带 `package.json` 和运行时依赖的后端是 **`week2-express/src/`**（W2 起一路累积到 W4/W6 的那套）。W3/W4/W6 目录只有 `notes/`，W5 是独立 demo 脚本，W7 是空壳，W8 只有前端。

含义：「复用上一轮哪个 Node 应用」在事实层面没有第二个候选，真正要决策的是**用它的哪个接口验收**。

另注意：`package.json` 位于 `week2-express/src/`，不在仓库根，也不在 `week2-express/`。部署单元的根目录是嵌套的第三层——这会影响 clone 路径、systemd 的 `WorkingDirectory` 和 `.env` 的落点。

### 2.2 启动入口的硬约束（`week2-express/src/server.js`）

| 事实 | 位置 | 对部署的含义 |
|---|---|---|
| `JWT_SECRET` 缺失或 < 32 字符直接抛错、`process.exit(1)` | `server.js:25-27` | 生产环境变量注入方式必须在 D1 定下来；这条是「服务起不来」的第一大概率原因 |
| 先 `connectDB()` 成功，才 `app.listen()` | `server.js:31,40` | 数据库没通，端口根本不监听。D2「Node 内部可验证」与 D3「数据库接通」的顺序需要重新想一遍 |
| 端口取 `process.env.PORT`，默认 3000 | `server.js:39` | 端口是可配置的，写进端口表时要写明「谁决定它」 |
| `app.listen(PORT)` **没有传 host 参数** | `server.js:40` | Node 默认监听 `0.0.0.0`（所有网卡）。「只在服务器内部监听」目前**不是**代码保证的，见问题 4 |
| 监听 `SIGINT` / `SIGTERM`，优雅关停，超时 30 秒强杀 | `server.js:69,106-107` | 进程守护方案的停止信号与超时必须与这 30 秒对齐，否则「重启恢复」验收会看到假象 |
| `npm start` = `node --env-file=.env server.js` | `package.json` scripts | 密钥读的是**工作目录下的 `.env` 文件**，不是环境变量注入。这决定了生产的凭据落盘方式和文件权限 |

### 2.3 数据库连接（`week2-express/src/config/db.js`）

`connectDB()` 只读 `process.env.MONGODB_URI`，没有任何默认值、没有重试、没有断线重连逻辑（依赖 mongoose 驱动自身行为）。

`.env.example` 里的样例是 `mongodb://root:example@localhost:27017/shop?authSource=admin`——这是**本地 docker-compose 的弱口令**（`docker-compose.yml` 里 `root/example` 明文）。它是本地开发样例，不能原样搬到服务器，也不能进部署文档。

### 2.4 候选验收接口的链路深度

| 接口 | 认证 | 触达数据库 | 链路覆盖 |
|---|---|---|---|
| `GET /` | 无 | 否 | 只证明 Nginx → Node 通（`app.js:33`） |
| `POST /auth/login` | 无（自身产出 token） | 是（查用户 + bcrypt 比对） | 证明到 Mongo，但需要预置账号 |
| `GET /reports/monthly-sales` | 需 token + admin 角色 | **两次**：`requireRole` 查角色，控制器跑聚合 | 覆盖最深；`routes/reports.js` + `middlewares/validateRoleMiddleware.js` |

事实补充：`requireRole` 在鉴权阶段就要读库（`validateRoleMiddleware.js:12`），所以 `403` 也代表数据库是通的——这在排障时是有用的信号，也意味着「数据库挂了」不会表现为 403 而是 500。

### 2.5 数据与测试的现状

- `seedUsers.js` / `seedOrders.js` 用固定随机种子生成 2000 个虚构用户和订单，**本身就是脱敏数据**，可以直接满足「空库或脱敏数据」的边界。
- 现有 3 个测试套件全部走 `mongodb-memory-server`（`__tests__/auth-flow.test.js:4`），**不接触真实网络和真实 Mongo**。含义：CI 全绿对生产链路零证明力，W9 的验收只能来自服务器上的真实请求。
- `.gitignore` 已忽略 `.env` 与 `.env.*`（保留 `.env.example`），但**服务器上的 `.env` 不在 git 保护范围内**，它的权限由部署方式决定。
