## 3. 建议的 W9 最小闭环

本周只保留一条主线：

```text
外部 HTTPS 请求
-> 反向代理
-> 仅在服务器内部监听的 Node 服务
-> 非公网暴露的 MongoDB
-> 返回一个可验证的真实接口响应
```

最低交付边界：

- 一个明确的目标应用和一个验收接口。
- 一个进程守护方案。
- 公网只开放完成访问所必需的端口；数据库不以公网直连作为验收方式。
- 域名 HTTPS 可访问，证书有效，并验证一次服务重启后的恢复。
- 部署文档不包含真实密码、Token、私钥或可复用凭据。
- 能按“请求经过哪些层、每层负责什么、失败时先查哪里”完成口述。

本周明确不扩展：

- 不同时实现 pm2 和 systemd 两套生产方案。
- Java 锚点只排在 Node HTTPS + MongoDB 主链通过之后，并受内存闸门约束；未完成不阻断 W9。
- 不提前进入 Jenkins、Docker 化流水线、AWS 多服务组合或自动回滚；这些属于 W11。
- 不提前做 3-5 类故障演练、集中日志平台和完整监控告警；这些属于 W10。
- 不做高可用、集群、Kubernetes 或完整生产灾备。
